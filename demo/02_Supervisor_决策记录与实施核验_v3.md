## 2. 为什么选择 Python，而不是 TypeScript

选择依据是本服务的工作重心和当前项目已有工程基础，不是语言性能或能力的普遍排名。

**Python 路线**将数据适配、统计、规则、受控计划和 Web API 放在同一服务中。quiz 已有 FastAPI、asyncpg、Alembic、httpx、pytest 等依赖基础，可参考工程组织而不复制其账号体系或整个依赖树。后端和 Vue 用版本化合同对接。

**TypeScript 路线**的优势是前后端类型习惯一致、便于参考 Beauty-AI 的 TS 规则；但前端视觉复用不要求后台也使用 TypeScript。现在不以迁移原型全部规则为任务，也不将原型代码当作已批准业务逻辑，因此该优势不足以改变本次选择。

工程组合定为：FastAPI、Pydantic 2、SQLAlchemy 2 + asyncpg、Alembic、httpx、pytest、Ruff；依赖锁定为 `uv.lock`。不强制使用多 Agent 或 LangGraph，不因为选择 Python 就自动开放脚本工具。

模型适配只依赖团队代理确认后的协议。代理地址、模型别名和 JSON Schema 支持尚未给出，不把任意供应商 SDK 作为硬依赖。

依据区分：项目依赖来自本轮读取的 `quiz/pyproject.toml`；框架机制的官方依据见主文档 W01–W03；语言取舍是本版决策。

## 3. 三种查询/工具方案的最终处理

### 3.1 采用的路径

```text
用户问题
→ 模型给出受限意图、已发布工具和参数
→ SV 校验 QuerySpec、工具权限和数据授权
→ ScopedReader 编译固定允许的查询结构
→ 业务库只读查询
→ 确定性计算和结果验证
→ SV 独立库保存记录
```

受限 QuerySpec 只描述已登记数据集、指标、维度、筛选值和排序选项。它不能包含 SQL 子句、自由表达式、物理列名、JOIN 或可调用函数。

这允许模型回答新的问法，不要求每种问法都新增一个工具；新数据来源、指标语义或物理关联仍通过研发发布，不交给模型临时发明。

### 3.2 模型写 SQL：不开放生产执行

只读账号限制写入，但不能自动限制当前用户读取范围、敏感字段、汇总推断或耗时。自动在任意 SQL 后追加 WHERE 也不能可靠限制 JOIN、子查询和比较基线。详见主文档 §9 及 W04、W06、W08。

因此本版不注册 `execute_sql`，不先做通用 SQL 审核器，更不把“只允许以 SELECT 开头”当作安全方案。新业务问题无法由当前目录表达时返回能力不足，不偷偷切换自由 SQL。

以后若单独评审探索性 SQL，只能在已授权的必要快照和独立受限环境里讨论，且需要输出隐私/资源限制；不是当前架构默认开放项。

### 3.3 模型添加工具：允许建议，不允许自己获得执行资格

| 动作 | 本版处理 |
|---|---|
| 选择已有工具及业务参数 | 允许，执行前校验 |
| 组合有界的已有工具步骤 | 允许，不能扩权限、递归或无限循环 |
| 保存一个分析配置/模板 | 可作为普通数据设计，执行时重新鉴权；不是新代码 |
| 提出工具名称、用途、参数 Schema 草稿 | 可保存为建议，不自动对其他用户发布 |
| 模型生成 Python/SQL 代码后立即执行 | 禁止 |
| 从数据库加载一段代码为新工具 | 禁止 |
| 模型安装依赖、修改服务源码、创建网络工具 | 禁止 |
| 研发根据建议实现工具、测试、审查、CI 后发布 | 正常研发流程，版本化注册 |

运行时工具注册表来自发布代码；数据库中有一条“工具草稿”并不赋予它任何可执行能力。用户在聊天里同意某个查询，也不等于授权修改生产服务程序。

## 4. 第 6 节落地检查：登录身份进入 SV

### 4.1 需要实现的最小对象

| 对象 | 责任 | 不应出现的内容 |
|---|---|---|
| `AdmAuthClient` | 固定地址调用 ADM 授权端点、适配 `CommonResult` | 任意转发 URL |
| `RequestPrincipal` | 当前请求可信主体 | 客户端自报角色 |
| `RunIdentity` | 固定本人、租户、会话/运行归属 | 用新 token 改 owner |
| `CredentialRef` | 受控内存中的访问凭据引用 | refresh token、永久明文 token 存储 |
| 请求守卫 | 身份、对象归属、Schema | 仅检查“能进入页面” |

### 4.2 明确的异常结果

无登录或失效登录直接调用 SV，必须失败；用户乙不能拿自己的 token 给用户甲的 run 重新授权。SSE 订阅、补发和读取旧报告不是登录豁免接口。

浏览器负责沿用 ADM 刷新登录，SV 只等待有效的新 token。创建、确认等请求自动重试沿用同一幂等键；不能刷新后重复创建运行。

初始部署一个 SV 应用进程、一个副本，数据库保存执行状态，凭据只在内存。进程重启后等待原主体重新授权，不假装已经具备跨副本凭据共享。

### 4.3 验收证据

保存请求头脱敏记录、主体对照、跨用户对象拒绝、401 刷新幂等、断线补发和重启等待重新授权测试。禁止把真实 token 写进测试报告。

## 5. 第 7 节落地检查：ADM 的一个授权适配

### 5.1 三个 purpose，而不是一批分析 API

| purpose | 什么时候用 | 返回什么 |
|---|---|---|
| `entry` | 入口、本人状态操作 | 可信主体和模块能力 |
| `authorize` | 读取业务数据前 | 本数据集的锚点、读取字段、输出字段、粒度、筛选和分组限制 |
| `verify_scope` | 旧结果读取、结果发往模型/Vue/交付前 | 原实际足迹是否仍有权 |

这些使用同一个拟定端点 `/system/supervisor/auth-context`；ADM 不返回完成率或报告。原有权限逻辑有必要抽取，但不在 SV 重写 `ht/rtm` 到数据范围的映射。

### 5.2 每个数据集必须交出一张权限真值表

真值表说明：权威 ADM 页面/服务是什么；汇总可用哪些对象；哪些对象可给员工明细；哪些字段受限；是否有周期结束后才可复盘的条件；租户/数据源如何绑定。

同一个员工在不同任务上的权限不能合并成“这个员工全部都可看”。授权对象可使用任务实例锚点，但其他数据集要定义合适锚点，不强制全都用 assignment。

授权超限不截断。业务字段读取许可与输出许可分开检查，不以“查询后删除敏感字段”代替读取授权。角色、空范围、元信息授权和 `complete` 字段的语义要写入合同；不能把空列表解释为全量。

### 5.3 旧报告验证不能只比较最新授权哈希

假设报告昨天使用实例 `{1001,1002}`，今天新派发了 `1003`。用户仍能看前两个实例，则昨天报告可按原截至时间阅读；不能因新增对象改变哈希就封锁。

若 `1002` 的权限被撤销，原报告的统计也可能含它，不能只删名字；整份派生正文暂不返回，要求新范围重算。原始 `DataFootprint` 需要包括全部分母、比较基线及输出字段/粒度，不仅包含展示的那几行。

### 5.4 必须关闭的工程缺口

| 缺口 | 核验方法 | 未完成时 |
|---|---|---|
| 现有地区字段是否足够 | 对照任务/人员/复盘服务完整分支 | 不直接当全部数据范围 |
| 不同 ADM 页面权限不同 | 给数据集指定权威基准，禁止取并集 | 不发布该数据集 |
| 授权数量与端点成本 | 小、中、大范围测对象数、响应大小和时间 | 明确缩小请求，不退化全量 |
| 历史对象或元信息权限 | 用 verify_scope 回归删除/调岗/复盘状态 | 无法验证则拒绝 |
| 数据库/租户绑定 | 读取真实配置和 DDL，验证关联 | 不猜 `tenant_id` |

这是工程核验清单，不要求用户凭空决定数据库列名或合理 ID 上限。

## 6. 第 8 节落地检查：工具与权限的映射

每个 `ToolSpec` 明确 `requiredPermissions`、数据集、结果粒度、参数/结果 Schema、效果类型和资源预算。功能权限、记录范围、字段/粒度、用户动作确认四者分别检查。

效果分为：

```text
READ_BUSINESS         只读业务数据
COMPUTE               在已授权快照上计算
WRITE_SV              写本人 SV 业务记录
REQUEST_ADM_DELIVERY  请求 ADM 发送已确认消息
```

自动保存运行、安全事件、证据和技术报告是内部行为，不通过模型“任意写表”工具实现。保存业务档案或发送消息只能调用窄方法，并使用服务端已验证对象。

`COMPUTE` 工具不能拿裸连接；`WRITE_SV` 工具不能写源业务；`REQUEST_ADM_DELIVERY` 不能提交任意 URL。模型工具列表按当前权限筛选，执行入口仍再次检查。

**验收重点**：未知工具、参数注入、授权列表注入、单人汇总推断、模型伪造确认、动态插件加载以及跨用户快照使用均失败。

## 7. 第 9 节落地检查：只读业务库、可写 SV 库

### 7.1 账号矩阵

| 身份 | 业务数据库 | SV 数据库 | 模型是否可直接使用 |
|---|---|---|---|
| `business_readonly` | 仅明确批准对象的读取 | 不承担状态写入 | 否 |
| `sv_runtime` | 无业务写权限，不应有业务读取授权 | 窄的状态/记录读写；安全事件只追加 | 否 |
| `sv_migrator` | 无业务权限 | 发布时 DDL/迁移 | 不在运行 Pod 中 |
| 模型 | 无连接凭据 | 无连接凭据 | 只能请求已发布工具 |

“独立数据库”允许共用物理服务器，但不允许退化为业务库里新增 schema。不能设置 FDW/dblink 或角色继承，让 SV 写账号绕回业务库。

### 7.2 查询链路

```text
ToolSpec + QuerySpec + AuthContext
→ 编译 AuthorizedQuery
→ 固定允许的锚点基础关系
→ 受控 JOIN / 聚合 / 字段投影
→ 只读短事务、超时、结果预算
→ DataFootprint 与证据
```

先限制范围再统计，不能全表算完再过滤。列名、分组和排序来自代码目录，值使用参数绑定。某角色不能看明细，就不能通过单人筛选或模型上下文获得等价信息。

### 7.3 状态写入与审计写入

数据访问开始前追加安全事件；SV 库不可用时不开始新查询。报告验证后在同一 SV 库事务保存报告、终态和完成事件，再推送。

跨业务读取和 SV 写入不建设分布式事务：取数成功而 SV 写失败，运行失败/待恢复，不假报已保存。业务库账号始终不承担任何“临时保存报告”的兜底。

人工编辑备注单独留痕，不能原地改报告事实。删除会话与安全日志清理使用不同权限和流程。

### 7.4 要测的风险

同一只读账号不会自动按用户隔离，仍由 `ScopedReader` 执行范围约束。工具是受审查代码，不是能够抵御任意恶意插件的安全沙箱；因此禁止运行时加载模型代码。

在测试库核验写入/DDL/带副作用函数、角色继承、PUBLIC 权限、取消后连接复用、多资源 JOIN、源字段漂移和跨用户足迹。不要对共享生产库执行未经批准的全库 REVOKE 试验。

## 8. 不依赖真实业务功能的人工验证样本

以下只用于验证权限与计算，不代表第一版要做课程完成率，也不来自真实业务库。

| anchorId | taskId | personId | 地区 | 测试状态 |
|---|---|---|---|---|
| 1001 | 501 | 11 | 南 | COMPLETED |
| 1002 | 501 | 12 | 南 | ASSIGNED |
| 1003 | 501 | 21 | 北 | COMPLETED |
| 1004 | 502 | 11 | 南 | COMPLETED |
| 1005 | 503 | 11 | 南 | ASSIGNED |

| 测试主体 | 汇总锚点 | 明细锚点 |
|---|---|---|
| 甲 | 全部五个 | 全部五个 |
| 乙 | 1001、1002、1004 | 1004 |
| 丙 | 1001、1002、1004 | 空 |

按测试约定“完成数 / 合法实例数”计算：甲为 3/5＝60%；乙、丙为 2/3≈66.67%。过滤 task 501 后：甲为 2/3，乙、丙为 1/2。

乙能看 person 11 的 1004，不意味着能看同人的 1005。丙虽然参与同一汇总测试，不能获取个人明细；仅汇总生产投影默认小样本抑制，故上面的数值是后台计算断言，不是小样本用户界面的展示断言。

### 足迹与变更测试

保存乙用 `{1001,1002,1004}` 形成的报告后，给乙新增 1005 授权，旧报告仍可读；撤回 1002 授权，旧报告及其派生消息不再返回。换成丙账号读取乙报告，即使范围相同，也因 owner 不同被拒绝。

### 写库与模型测试

业务连接尝试写入测试表必须被拒绝；SV 连接保存该测试报告成功。代理桩提出未登记工具、任意 SQL 或伪造确认时不执行。代理未配置时仅使用标明测试来源的结构化运行验证，不能冒充真实在线模型。

## 9. 飞书实施核验，不另建发送体系

已有代码证据是 ADM 的任务通知/周期报告、群绑定、投递及重试。具体是否能直接发送 SV 报告，需要定位正式内部接口；不能将 `/config/test`、`/binding/test` 或周期测试接口当生产发送接口。

| 项目 | 决定 / 核验要求 |
|---|---|
| 主记录 | SV 审计、报告、交付意图在 SV 库 |
| 飞书凭据 | 只在 ADM |
| 对接方式 | 合适正式能力直接复用，否则新增窄的适配和状态查询 |
| 发送内容 | 默认无业务数据通知 + 鉴权链接；真实业务内容须验证接收方范围 |
| 接收人 | ADM 允许的绑定，禁止模型任意指定地址 |
| 用户确认 | 绑定 payload 哈希、报告版本、接收人及主体，5 分钟有效 |
| 投递状态 | ACCEPTED 与 SENT 分开；不伪造已读 |
| 超时 | UNKNOWN，原幂等键查状态，不直接重复发送 |
| 群消息 | 收到链接不获得报告权；本人私有报告不自动共享 |

SV outbox 与 ADM 投递记录分别保存自己负责的状态。网络超时后“到底发了没有”需靠回执和幂等合同解决，不用本地事务宣称跨服务恰好一次。

## 10. 团队代理：只待部署信息，不再待模型供应商选型

部署方需要提供：代理入口、协议类型、鉴权方式、Secret 引用、模型别名、私有 CA（若有）、限流/超时、工具调用和结构化输出能力说明。

工程负责验证：Header 不泄露、只向固定代理发送、代理错误映射、取消/超时、输出 Schema、未知工具、使用量字段和日志脱敏。OpenAI-compatible 只是可能的接口形式，当前没有依据断言已支持。

没有代理配置时自然语言能力显示未配置。已经确认的结构化查询可以继续进行确定性测试/模板处理，但不能把未理解的问题当作已分析；不开放个人备用 Key，不自动切公网供应商。

## 13. 工程交付关口

**合同关口**：形成授权三种 purpose、数据足迹、工具效果、QuerySpec 和结果 Schema；列出真实证据与未知项。不是先确定一串审计业务功能。

**数据关口**：在隔离测试环境验证源数据只读、用户范围和字段约束、SV 独立库写入；含同用户跨任务、空范围、取消/重复请求和写库故障。

**运行关口**：会话、队列、租约、事件、报告、足迹、幂等和恢复可复现；没有凭据时等待同一用户重新授权。

**模型关口**：唯一团队代理；工具计划受限；SQL/自生成代码不可执行；引用和数字验证有效；失败状态真实。

**界面关口**：一级入口；与课件页同基线对比；历史内容鉴权；取消与断线区分；不显示无效或模拟业务能力。

**交付关口**：对已启用的飞书路径核验确认、接收方、幂等、UNKNOWN 对账；验证部署网络、CI 与回滚。

每个关口保存代码 SHA、契约版本、样本、期望、日志和截图。只在各仓库 `test` 分支实施，使用范式中文提交，推送后检查 `https://ci.hinihao.net/repos`；不覆盖其他工作或夹带他人提交。
