# 智能巡检产品工作台

本阶段只实现前端产品原型与本地业务数据，不接真实后台、模型或飞书。界面按正式产品呈现，不出现体验卡、演示标签、脚本推进或模拟说明。完整领域契约见 [统一需求与两类业务](./inspection-request-contract.md)。

## 页面
- `/data-audit` → `CoursewareInspectionWorkspace.vue`。入口卡最大1440px、24px圆角，自适应可用区域；左侧“智能巡检工作区”引导，右侧运行中/已完成两类任务。
- 新建、查询和修改 → `UnifiedInspectionSession.vue`。无链式阶段条；默认左对话、右材料，允许中间按钮620ms平移交换，输入固定在交互卡底部。右侧常驻分析汇报、执行过程、数据明细。
- 监督详情由阶段汇报、实时进展、完成事项组成。导航、暂停/恢复、修改置于首卡左上；右上使用已确认的任务说明作为标题，下方条件与汇报独立滚动。完成事项区域已增大。
- 暂停仍归运行中；`completedAt`表示已结束/完成。完成查询可重新查看快照和明细，完成监督不可再恢复或修改。

## 业务数据与接入
- `coursewareInspectionRuntime.ts`按用户ID与角色提供共享runtime，`coursewareInspection.ts`处理规则、记录、归档、提醒及查询。
- 正常课件store的`setTask/refreshTask`消费已有生成快照；终态按产物ID补查metadata。系列课件分别核验，使用`estimatedDurationSeconds`，不以生成前目标时长代替。
- `trainingInspection.ts`提供培训范围、达标标准和人员记录。新培训记录通过`processTrainingRecord`核验，与课件生产者分开。
- `captureTaskContext`防异步课件回包串号；查询另外使用身份变更版本及逐页守卫。
- 初始提醒`notificationState:inbox`不会刚进入首页就弹窗；真实生产者的新提醒由全局`CoursewareGenerationPrompt`提示。本人明确签收不等于整改达标。
- 内部`simulated`仅说明本地回执来源，UI显示业务汇报记录；代码不会发送真实消息。
- `inspectionEvaluation`保留核验事实，停止跟进不抹去原有达标/未达标判定。

## 核对路径
1. 首页运行中仅核对课件/培训监督，已完成核对查询及结束监督；初始为11项、5项运行中监督、6项已完成记录。
2. 新建一次查询并最终确认，实际读取完成后进入已完成；打开历史查询查看读取、筛选、核验、汇总与数据明细，不存在进行中查询样本。
3. 打开课件或培训监督，观察每组业务事件滚动，完成后在下卡展开原样过程；上翻不强拉，暂停/隐藏/离开不新增事件。
4. 新建培训需求如“查一下南区李欣的新品培训是否达标”，补齐时间和标准，确认后查看筛选出的人员记录。
5. 新建持续需求，补齐范围、时间、标准及提醒动作，确认后继续在会话中观察过程或补充要求。
